# Static Analysis Guide

## Purpose

The repository uses clang-tidy for C++ static analysis and clangd for editor
diagnostics. Both consume the compilation database generated by the
`windows-clang-debug` CMake preset.

## Configure the Compilation Database

Set `VCPKG_ROOT` and configure through the repository build entry point:

```powershell
$env:VCPKG_ROOT = 'C:\path\to\vcpkg'
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Invoke-Build.ps1 -Operation Configure
```

This creates `out/build/windows-clang-debug/compile_commands.json`. The first
configure may take several minutes; do not clear the vcpkg caches or installed
packages.

## Run clang-tidy

The helper delegates to the shared build entry point, so analysis uses the same
discovered Visual Studio and LLVM environment and the compilation database
under `out/build/windows-clang-debug`.

Run it over C++ files under `app/` and `core/`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-clang-tidy.ps1
```

Or provide one or more source paths:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-clang-tidy.ps1 core\render\graph\RenderGraph.cpp
```

## Editor Integration

The Zed configuration passes
`--compile-commands-dir=out/build/windows-clang-debug` to clangd. Other editors
can point clangd at the same directory.
